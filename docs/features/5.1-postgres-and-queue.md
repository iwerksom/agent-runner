# 5.1 Postgres and a queue, with a separate worker

**Phase 5** · **Status: Planned**

## User story

As a **operator** I want **runs to execute in a worker process that outlives the web process** so that **a restart of the console never loses or kills a run**.

## Issues

- [#22](https://github.com/iwerksom/agent-runner/issues/22) Postgres and a queue; a separate worker process replaces the in-process runner (open)

## Acceptance

- The web tier no longer imports the Agent SDK and holds no `ANTHROPIC_API_KEY`.
- A run survives a web-tier restart: reconnecting to SSE replays persisted events, then resumes live.
- Two runs on the same repo execute concurrently in separate worktrees.
- `bus.ts` is replaced by a Postgres `LISTEN/NOTIFY` implementation and no other file changes.
- The JSON-as-TEXT columns become `Json` and the String status columns become enums.

## Notes

Redis and BullMQ, which this phase originally named, are dropped (DECISIONS #21 to #26).
