# 2.2 The gate refuses what it should, and nothing else

**Phase 2** · **Status: In progress**

## User story

As a **operator** I want **the write-scope gate to refuse unsafe commands and reads, and not refuse safe ones** so that **agents run unattended without escaping their scope or wasting turns**.

## Issues

- [#12](https://github.com/iwerksom/agent-runner/issues/12) Pipeline-filter escape: ls | awk allowed for a read-only agent (closed)
- [#14](https://github.com/iwerksom/agent-runner/issues/14) The CLI auto-approves read-only commands before canUseTool sees them (closed)
- [#37](https://github.com/iwerksom/agent-runner/issues/37) The gate splits on | inside quotes (closed)
- [#27](https://github.com/iwerksom/agent-runner/issues/27) Reads are not confined: a read-only agent can read any file the console user can (open)
- [#15](https://github.com/iwerksom/agent-runner/issues/15) User-level skills from ~/.claude load into runs (open)

## Acceptance

- No allow-listed command can run arbitrary code (#12) and the gate runs ahead of CLI auto-approval (#14).
- Separators inside quotes do not split a command (#37). The safe-filter exemption applies only after a pipe (#27, PR #47).
- `Read`, `Grep` and `Glob` stay inside the worktree and never open `.env` secrets (#27, PR #48).
- Still open: Bash operands of allow-listed programs can read any path until 2.1 (#27); user-level skills were the other open item (#15), now resolved for sandboxed runs (DECISIONS #31).
