# 8.2 Hosted team deployment

**Phase 8** · **Status: Planned**

## User story

As a **team lead** I want **one hosted Arnold that my developers sign in to** so that **caps, history, findings and credentials are shared and nothing sensitive lives on a laptop**.

## Issues

- [#57](https://github.com/iwerksom/agent-runner/issues/57) Hosted team deployment: where it runs, secrets, backups, repo access (open)

## Acceptance

- One central deployment: web, worker, Postgres and the LLM gateway, brought up with a single `docker compose up`. Solo mode is the same file with auth off.
- Decisions are recorded for: where it runs, how secrets reach the gateway and the sandbox, how the worker gets access to each team's repos, backups and restore, how updates roll out without losing a running run, and TLS and who may reach the port.
- Backup and restore are tested, not just written down.
- Agents that need a locally-bound resource use the local-session runner (`docs/architecture.md` Section 13): only that executor runs on a laptop, and the control plane stays central.

## Notes

Hosting only the database and running the app on each developer's machine was considered and rejected: every machine would have its own budget, queue and secrets, and the sandbox, audit trail and shared findings could not be enforced centrally.

Needs Phase 5 (Postgres, worker) and Phase 4 (gateway); built with 8.1.

Phase detail: `docs/ROADMAP.md`.
