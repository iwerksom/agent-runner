# 3.2 Run results reach the checkout

**Phase 3** · **Status: In progress** (#78 done; #79 planned)

## User story

As a **maintainer of ledtraad** I want **the changes a `working-tree` agent makes to reach my checkout without typing a diff command** so that **I can review and keep an agent's fixes in a few clicks, and the agent never needs the power to commit**.

## How results are delivered

A `working-tree` run edits a worktree inside Arnold's mirror, which is not the repo's checkout. Today the only way to get its edits is `git -C <worktree> diff | git apply`, found on the first verified `ledtraad-pre-pr-review` run. Arnold, running on the host and not in the sandbox, delivers the result after the run. The agent keeps its limits: no git writes, and a read-only mirror.

A per-agent manifest setting, `onChanges`, chooses how:

| Setting               | What happens                                                                                                                                                       | Risk                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| `patch` (**default**) | The diff is stored as the run artifact `changes.patch` and shown on the run page, with an **Apply to checkout** button.                                            | None: nothing changes without a click.                             |
| `branch`              | Arnold commits the changes on `arnold/<agent>/<run>` and fetches that branch into the checkout as a ref. The checkout's own branch is untouched.                   | Low.                                                               |
| `commit`              | As `branch`, then fast-forwards the checkout's branch, only if its tip still equals the run's base SHA and the tree is clean. Otherwise it falls back to `branch`. | Moderate: it moves the branch pointer, so it is fast-forward only. |
| `push`                | The existing `branch-push` tier.                                                                                                                                   | Highest: needs a token. Stays a separate tier.                     |

Arnold writes the commit message (agent and run), not the model.

## Acceptance

- A `working-tree` run that changed files stores `changes.patch`; a run with no changes stores none.
- **Apply to checkout** works only on a clean checkout whose branch is the run's base, never commits and never switches branches, and says why when disabled.
- `onChanges` is a validated manifest field, default `patch`; `branch` and `commit` behave as in the table, and `commit` never merges, rebases or forces.
- The run row records whether the patch was applied, or the branch and commit it produced.
- `pnpm smoke` covers each mode and each refusal.
