# 6.2 Onboard a repo with existing agents

**Phase 6** · **Status: Planned, waits for 6.1**

## User story

As an **operator** I want **to pick existing agents for a newly added repo, fill in that repo's values, and get runnable bindings** so that **onboarding a repo needs no code change and no restart**.

## Issues

- [#67](https://github.com/iwerksom/agent-runner/issues/67) Onboard a repo with existing agents from the console (open)

## Acceptance

- From the console, an operator chooses agents for a repo and is asked for what is repo-specific: documents to audit and measurement commands, the tracker (GitHub or Jira), the default branch, the timezone, and the toolchain commands an allow-list needs.
- The binding is validated before it is saved, and the agent runs on the new repo without a code change.
- One agent definition can be bound to several repos with no id clash (the key is `(definition, repo)`, 6.1).

## Notes

Today a new repo means copying a binding file under `registry/<slug>/` and prefixing every agent id, because the agent id is global (#16). Feature 6.1 turns bindings into data in their own repository; this feature puts a flow on top of it. Not scheduled earlier: until then, agents are added to a repo by hand, as feature 3.1 does for ledtraad.
